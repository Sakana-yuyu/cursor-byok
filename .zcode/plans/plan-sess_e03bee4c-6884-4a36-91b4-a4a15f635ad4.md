# 完成计费：内置官方价格 + 探测中转站价格 + 价格优先级

## 总体设计

### 价格三级优先级（高→低）
1. **手动配价**：用户在 ModelEditor 手动填的（已有，`Pricing.Source="manual"`）
2. **中转站探测价**：启动时 AutoMatch 从 `/v1/models` 解析的（`Pricing.Source="catalog"`）
3. **内置官方价**：catalog.go 内置的官方公布价格（`Pricing.Source="builtin"`）

手动配价优先，没有手动配价时用探测价，都没有时用内置价。三者合并后注入 `PriceLookup`。

## 改动清单

### 1. `internal/modelcontext/catalog.go` — 内置官方价格表

在 `Capability` 结构加价格字段（复用已有的 `MaxOutputTokens` 模式）：
```go
type Capability struct {
    // ...现有字段...
    Pricing *BuiltinPricing // 新增：官方公布价格（每百万 token，USD）
}

type BuiltinPricing struct {
    Input      *float64
    Output     *float64
    CacheRead  *float64
    CacheWrite *float64
}
```

给现有 capabilityRules 里每个模型族填入官方公布价格（Claude/GPT/Gemini/Grok/Qwen/DeepSeek/Kimi/GLM/MiMo/MiniMax/StepFun），数据来源是各家官方 pricing 页面。

新增访问函数：
```go
func BuiltinPricingFor(modelID string) *BuiltinPricing
```

### 2. `internal/app/runner.go` — 价格合并逻辑

修改 `priceRatesFromAdapters`：
- 遍历每个 adapter
- 如果 `adapter.Pricing != nil`（手动或 catalog）→ 直接用，`Known=true`
- 如果 `adapter.Pricing == nil` → 查 `modelcontext.BuiltinPricingFor(adapter.ModelID)`
  - 找到 → 构造 `PriceRate`，`Known=true`，标记来源为内置
  - 没找到 → 跳过（保持现状，显示"未配置价格"）

这样**不需要改 config 持久化**——内置价格在运行时注入，不写入 config.yaml。

### 3. `internal/client/auto_match_context.go` — catalog 探测价格回填

修改 `AutoMatchContextWindows`：
- 第一遍 catalog 命中时，除了写 `ContextWindowTokens`，还检查 `item.Pricing`
- 如果 `item.Pricing != nil` 且 adapter 当前 `Pricing == nil` → 写入 `adapter.Pricing = {Source:"catalog", Known:true}`
- 保存到 config（已有 SaveUserConfig 流程）

**注意**：只在 adapter 没有手动配价时回填（`Pricing == nil`），避免覆盖用户手动设置。

### 4. `frontend/src/components/HomeMetricsCard.vue` — 价值估算显示优化

当前 `rangeCostSummary` 用 `pricingKnown` 判断是否计价。内置价格注入后 `Known=true`，所以会自动显示金额。

调整 tooltip 文案，说明价格来源（手动/探测/内置）：
- 在 `RequestMetric` 或聚合层不增加字段（避免改 proto），而是在 tooltip 文字里说明"价格基于官方公布价"

### 5. `frontend/src/views/ModelEditor.vue` — 价格编辑器增强

在价格编辑面板显示当前生效价格来源：
- 如果 `Pricing.Source == "builtin"` → 显示"官方内置价（覆盖请手动填写）"
- 如果 `Pricing.Source == "catalog"` → 显示"中转站探测价"
- 如果 `Pricing.Source == "manual"` → 显示"手动配价"

## 关于余额

余额查询功能已完整实现（`provider_balance.go` 有6种策略 + named providers），`SupplierDetail.vue` 已能显示实时余额。

首页"价值估算"是**累计花费**（token×单价的向后统计），与余额（当前剩余）是不同维度。本次**不改动首页价值估算的语义**——它继续显示估算花费。如果某个供应商支持余额查询，用户在 `SupplierDetail` 详情页已经能看到实时余额。

（如果你确实想在首页显示余额而不是花费，请另行确认——这会改变首页卡片的语义。）
