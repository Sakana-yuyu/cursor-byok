# 桌面浮窗与运行环境判定修复设计

## 问题

打包程序使用 `window.runtime` 判断是否为 Wails 桌面环境。当前 Wails v3 运行时并不保证暴露该对象，导致桌面包被误判为浏览器预览：服务控制调用 mock，统计浮窗按钮则在主窗口内路由到 `/stats-overlay`。

后端日志已确认代理服务本身成功启动，因此不修改服务启动链。

## 设计

- 桌面构建默认使用真实 Wails bindings。
- 仅当 Vite 以 `browser-preview` mode 运行，或显式设置 `VITE_BROWSER_PREVIEW=1` 时启用浏览器 mock。
- 首页浮窗按钮在桌面环境只调用 `OpenStatsOverlayWindow`，不执行主窗口路由跳转。
- `/stats-overlay` 路由保留，供独立原生窗口加载，也允许浏览器直接访问以预览样式。
- 浮窗独立于通用 `MainLayout`，避免标题栏、窗口按钮和主页面布局进入浮窗。
- 原生浮窗固定为 240x120、不可缩放、无边框、始终置顶、任务栏隐藏，并允许拖动。
- 重复点击首页按钮切换浮窗显示与隐藏。

## 验证

- 浏览器开发预览仍能打开首页和 `/stats-overlay`。
- Windows 打包程序的服务状态来自真实 bridge，启动/停止按钮调用真实服务。
- 点击“浮窗”后主窗口路由不变化，桌面出现独立 240x120 置顶窗口。
- 浮窗无主窗口标题栏、无任务栏项，可拖动且不可缩放。
- Go 构建、前端构建和最终 Windows 打包成功。
