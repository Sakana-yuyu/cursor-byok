# 统计浮窗贴边形变设计

## 问题

统计浮窗贴边后需要缩成胶囊，同时保证鼠标悬浮时只执行一次展开，并始终向远离贴边的一侧扩展。固定使用 `44x86` 或 `112x36` 会让不同浮窗样式在完整轴方向被裁切，也会让展开后的窗口离开原贴边位置，触发重复进入和离开。

## 方案

原生窗口与前端内容使用同一套锚定形变规则：

- 左右贴边收缩为 `44 x 当前样式完整高度`，右侧固定右边缘、左侧固定左边缘。
- 上下贴边收缩为 `当前样式完整宽度 x 36`，顶部固定上边缘、底部固定下边缘。
- 未贴边但锁定时使用 `112x36` 胶囊。
- 贴边 inset 为 `0`，窗口与对应屏幕工作区边缘贴合。
- 悬浮展开和离开收缩都从当前锚点直接改变窗口尺寸，不再叠加插入、位移或二次抖动动画。
- 尺寸更新只负责布局；窗口置顶由独立偏好接口更新，避免 morph 携带旧值覆盖设置。

这样最小浮窗在完整轴方向与展开后的浮窗一致，鼠标仍位于恢复后的窗口范围内，不会因窗口位置跳变反复触发收缩。

## 状态同步

- 贴边、锁定、自动收缩和置顶偏好在主窗口与浮窗之间双向同步。
- 托盘重新打开浮窗时恢复持久化坐标，并将失效坐标夹取到当前显示器工作区内。
- 开启或关闭自动收缩、锁定状态变化时立即转换到对应形态，不等待下一次鼠标事件。

## 验证

- 运行 `gofmt`、`go test ./...` 和 `go build ./...`。
- 连续运行两次前端 production build，确认 i18n 目录稳定。
- 静态和人工核对四个贴边方向、悬浮展开、离开收缩、托盘恢复、置顶切换和跨窗口偏好同步。
- 不新增测试文件，不提交本地 GUI 截图。

## 范围

- 不修改统计数据来源、刷新周期、贴边阈值或已确认的视觉样式。
- 不修改已安装的 Cursor 客户端，不生成或提交发布构建产物。
