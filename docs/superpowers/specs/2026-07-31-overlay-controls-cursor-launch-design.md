# 浮窗控制、关闭策略与 Cursor 启动设计

## 背景

统计浮窗顶部仍保留了不必要的标题区域，主窗口关闭行为固定为隐藏到托盘，浮窗偏好和启动坐标需要更完整地恢复。Windows 首页的一键启动 Cursor 目前只在自动检测成功时显示，且没有人工路径兜底。

## 目标

- 卡片、引擎、球形三种浮窗直接呈现主体内容，不显示标题或状态点占位。
- 浮窗保留必要的图标操作：贴边收缩、隐藏浮窗、关闭应用，并为陌生按钮提供 tooltip。
- 主窗口关闭支持“隐藏到托盘”和“直接退出”，选择可在设置中修改并持久化。
- 浮窗关闭支持“隐藏浮窗”和“关闭应用”，并提供托盘菜单重新显示浮窗。
- 浮窗的样式、置顶、显示状态、贴边收缩、锁定状态和屏幕坐标持久化，启动时恢复。
- Windows 始终显示 Cursor 启动入口；自动检测失败时允许填写并保存 `Cursor.exe` 路径。

## 方案

### 浮窗布局

移除浮窗标题文字和状态点，去掉对应的呼吸动画及无效加载状态。主体内容不再依赖标题行占位。控制按钮使用独立的操作区域，保持不遮挡卡片、仪表或球形主体，并沿用现有贴边形变与防抖逻辑。

浮窗操作分为：

- 贴边收缩开关：保留现有功能。
- 隐藏浮窗：保存 `visible=false`，关闭统计浮窗窗口但不退出应用。
- 关闭应用：按主窗口关闭策略执行，默认隐藏到托盘。

### 关闭与托盘

在设置中增加持久化的关闭策略字段：

- `tray`：隐藏到托盘，应用进程和代理服务继续运行。
- `quit`：执行现有的退出清理流程后退出应用。

原生主窗口关闭钩子读取当前运行时策略。前端启动后将持久化策略同步给原生窗口服务；在同步前使用默认的 `tray`，保证旧配置和启动早期关闭事件安全。托盘菜单增加“显示统计浮窗”，调用现有显示流程并恢复保存的样式、置顶和坐标。

浮窗关闭操作通过已有窗口服务和统一状态函数执行，避免只关闭原生窗口而留下 `visible=true` 的脏状态。所有设置变更先规范化，再持久化，最后同步原生窗口。

### 浮窗偏好与坐标

继续使用现有浮窗偏好存储，扩展规范化字段：

```text
style, alwaysOnTop, visible, x, y, snapCollapse, dockLocked, closeAction
```

窗口拖动后的坐标继续由浮窗轮询保存。恢复时区分“没有保存坐标”和合法的 `(0, 0)`，避免屏幕左上角位置被误判为未设置。恢复坐标前根据当前屏幕工作区进行边界修正，避免显示器切换后浮窗出现在屏幕外。

### Cursor 检测与手动路径

增加统一的 Cursor 路径解析流程：

1. 使用用户保存的手动路径，并验证它是可执行文件。
2. 检查 Windows 常见安装目录、PATH 和可用的卸载信息。
3. 找不到时返回可操作的错误，不隐藏启动入口。

设置页提供路径输入、自动检测和保存操作。启动按钮调用统一解析结果；手动路径优先于自动检测。非 Windows 平台保留现有检测逻辑，不引入平台特定 UI。

## 数据流与错误处理

- 前端设置变更统一经过 `setStatsOverlayPreferences` 或对应的 Cursor 设置函数规范化和持久化。
- 原生窗口服务只负责窗口生命周期、关闭策略同步、坐标恢复和 Cursor 进程启动，不直接读取前端 `localStorage`。
- 启动 Cursor 失败时保留用户输入路径，并显示明确错误，不清空已保存路径。
- 浮窗关闭、托盘显示和应用退出都必须更新 `visible`，避免下次启动错误恢复已关闭的浮窗。
- 旧版本缺失字段时使用兼容默认值：关闭策略为 `tray`，浮窗显示为关闭，Cursor 手动路径为空。

## 验收标准

- 三种浮窗打开后主体内容直接可见，顶部没有“实时统计”、状态点或空白标题占位。
- 主窗口关闭可分别验证隐藏到托盘和直接退出，重启后策略保持。
- 浮窗关闭后可从托盘重新显示，样式、置顶、贴边设置和坐标保持；屏幕左上角坐标也能正确恢复。
- Windows 未检测到 Cursor 时仍显示启动按钮和路径设置；填写有效路径后可启动 Cursor，重启后路径仍在。
- 自动检测到的 Cursor 路径可以被手动路径覆盖，清空手动路径后恢复自动检测。
- `npm --prefix frontend run build`、`go build ./...` 和 `git diff --check` 通过。

## 范围与约束

- 不改变代理服务、模型配置、统计数据来源和既有贴边动画的行为。
- 不新增测试文件，遵循仓库现有测试约束；使用构建、静态检查和可复现的路径/状态场景验证。
- 不提交构建产物。
