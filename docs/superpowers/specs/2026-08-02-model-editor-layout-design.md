# ModelEditor 布局优化设计

## 背景

`ModelEditor` 当前把供应商模板、基础字段、模型能力、协议参数、请求头、余额查询和读图 MCP 连续平铺在同一个滚动表单中。字段本身完整，但信息层级不明显，首屏密度高，用户难以区分“创建连接”与“高级调优”。

## 目标

1. 同时优化快捷添加模式和完整编辑模式。
2. 保留所有字段、自动填充、保存、测试、模型拉取和校验逻辑。
3. 让供应商与连接信息在首屏可见。
4. 把高级配置从首屏移出，并保持可访问、可键盘操作。
5. 桌面端减少横向拥挤，窄窗口不产生横向溢出。
6. 继续使用单一纵向滚动容器，避免下拉菜单和页面互相抢滚轮。

## 非目标

- 不重构 `appState`、保存接口、模型目录接口或后端协议。
- 不改变 `supplierID`、模型类型、协议分组和余额查询的业务语义。
- 不新增测试文件；遵循仓库测试约束。
- 不将完整编辑器拆成新的路由或组件体系。

## 方案

采用“分层卡片 + 高级设置默认收起”的布局方案。它比步骤式表单少一套状态机，比左右分栏少一套响应式切换，同时能直接利用现有 `advancedExpanded` 状态。

### 页面骨架

```text
固定顶部栏
├─ 标题
└─ 取消 / 保存并测试 / 保存

滚动内容区
├─ 快捷添加模式
│  ├─ 供应商与连接
│  └─ 拉取模型
└─ 完整编辑模式
   ├─ 供应商与连接
   ├─ 模型标识
   ├─ 模型能力
   └─ 高级设置（默认收起）
      ├─ 协议与端点
      ├─ 请求参数
      ├─ 自定义请求头
      ├─ 余额 / 套餐查询
      └─ 读图 MCP
```

## 布局规则

### 快捷添加模式

- “模型类型”和“归类方式”保持两列。
- “供应商模板”占整行，位于连接地址之前。
- 供应商模板、接口地址、访问密钥保持主要视觉层级。
- 备注和拉取模型动作放在连接区域尾部。
- 保留当前供应商下拉图标和独立滚动行为。

### 完整编辑模式

- 供应商与连接卡片放在最上方。
- 模型标识区域包含显示名称、用户分组名称、模型标识、模型候选/预设。
- 模型能力区域包含上下文窗口、最大输出、推理强度和价格。
- 协议摘要按钮保留当前状态展示：自动/固定、当前协议分组。
- `advancedExpanded` 为 `false` 时高级字段不占用首屏空间；展开后保持现有字段顺序和绑定。
- 长地址、JSON 和模型目录 URL 使用整行布局。

### 视觉系统

- 内容区使用 `mx-auto` 与合理最大宽度，避免大屏横向铺满。
- 卡片使用项目现有深色背景、边框、圆角和绿色 focus 状态。
- 卡片标题采用统一的小字号标题 + 辅助说明，不重复解释同一行为。
- 两列只用于语义相关且内容短的字段；长文本字段不强行两列。
- 顶部操作栏保持固定，避免用户滚动到页面底部才能保存。

### 响应式

- 桌面宽度下核心短字段使用两列。
- 窄窗口自动变为单列。
- 页面只保留一个纵向滚动容器。
- 供应商下拉继续使用 `Select` 的 `overflow-y-auto` 与 `overscroll-contain`，不会触发页面滚动。

## 数据和交互约束

- 供应商选择继续调用 `handleSupplierChange` 和 `applySupplierTemplate`。
- 自动填充只写入模板允许的默认值，不覆盖用户已经输入的值，除非当前已有的强制模板逻辑明确要求覆盖。
- 所有 `v-model`、按钮事件、错误状态和异步请求保持不变。
- 高级设置的收起/展开按钮必须是可聚焦按钮，并保留当前旋转箭头状态。
- 错误提示放在所属卡片内，避免与其他字段产生距离过大的关联。

## 文件边界

主要修改：

- `frontend/src/views/ModelEditor.vue`

必要时只调整：

- `frontend/src/components/ui/Select.vue`（仅为保证已有滚动行为不回归）

不修改：

- `frontend/src/state/appState.js`
- `frontend/src/utils/supplierCatalog.js`
- 后端和请求协议代码

## 验收

1. 快捷添加模式和完整编辑模式均可正常进入、编辑和保存。
2. 首屏可见供应商模板、接口地址、访问密钥和模型标识。
3. 高级设置默认收起，展开后所有原字段可编辑。
4. 供应商自动填充、模型预设、模型目录、余额查询、保存和测试行为不变。
5. 供应商长列表只滚动下拉浮层，不滚动页面。
6. 1100px 左右窗口和窄窗口没有横向溢出或字段重叠。
7. 执行 `npm --prefix frontend run i18n:scan`、`npm --prefix frontend run build`、针对编辑文件的 lint、`git diff --check` 和本地 HTTP 检查。
