# SupplierDetail 余额操作区布局设计

## 背景

供应商详情的余额操作区把测试按钮、同步按钮、说明文字、查询结果和同步结果放在同一个可换行容器中，导致按钮层级和状态信息混杂。

## 目标

- 测试余额和同步配置视觉上分成两个独立操作。
- 保留现有测试、同步、保存和错误处理逻辑。
- 桌面端并列展示，窄窗口自动单列。
- 查询结果和同步结果分别归属对应操作。

## 设计

```text
余额操作
├─ 测试余额
│  ├─ 说明：使用当前未保存的连接与余额配置
│  └─ 查询结果 / 错误状态
└─ 同步余额配置
   ├─ 操作：同步到同 URL 分组
   ├─ 说明：保留各分组 API Key
   └─ 同步结果 / 错误状态
```

每个操作使用独立的深色卡片，测试按钮使用主要操作样式，同步按钮使用次要操作样式。状态信息在操作卡片内部整行显示，避免与按钮在同一行互相挤压。

## 约束

- `testBulkEditBalance`、`syncBalanceToSameURL`、`balanceTestState`、`balanceSyncState` 和 `sameURLGroupCount` 不改变。
- 不增加新的业务状态。
- 现有保存/取消区域保持原位置和行为。
- 不引入第二个滚动容器。

## 验收

1. 桌面宽度下两个操作卡片并列且按钮、说明和状态对齐。
2. 窄窗口下卡片单列显示，文字不溢出。
3. 测试中、测试成功、测试失败、同步中、同步成功和同步失败状态仍正确显示。
4. 前端 i18n 扫描、构建、lint、diff 检查和本地页面 HTTP 检查通过。
