# Proposal: cursor-multi-account-management

## Why
当前助手只有一个 Cursor 控制面账户，无法在多个官方账户之间安全选择、迁移或恢复；真实 Cursor 登录态又与助手授权共用敏感凭据，直接绑定切换会关闭客户端并造成状态覆盖。
本变更建立多账户库、显式客户端切换和可恢复操作边界，同时保留旧单账户调用一个发布周期。

## What
- 将单凭据文件升级为受限账户库、索引和当前指针，完成式迁移旧文件，并让控制面授权与刷新只作用于当前账户 | refs: R-2, R-3 | verify: 迁移、索引自愈、当前账户刷新竞态和旧接口兼容测试通过。
- 支持 OAuth 会话、本机白名单、Token、恢复 JSON 导入，以及经二次确认的凭据恢复包导出；列表、删除和导出结果只返回非敏感摘要 | refs: R-2, R-3 | verify: 输入边界、去重、导出文件格式/权限和 DTO/日志无凭据测试通过。
- 增加准备/确认/执行式 Cursor 客户端账户切换，关闭进程后备份 `state.vscdb`、WAL、SHM，只写认证白名单并在失败时恢复文件和旧 current | refs: R-2, R-3 | verify: 临时 SQLite 成功、锁冲突、写入失败、校验失败和重启失败场景均保持可恢复。
- 扩展 Wails、`clientApi`、浏览器预览和账户面板，区分“设为助手当前账户”“切换到 Cursor”“导出凭据”，同步 i18n 与 bindings | refs: R-2, R-3 | verify: 单元、构建、i18n 和 Playwright 覆盖空态、登录、导入、确认、删除、导出与错误反馈。
- 增加精确敏感文件忽略规则和分层验收，分别记录 Go/构建、browser-preview、桌面绑定与经再次授权的真实 Cursor E2E | refs: R-2, R-3 | verify: 暂存清单无数据库/凭据，CI 等价命令通过，真实 E2E 未授权时明确保持未验证。

**Not in this change**: 自动轮换、配额驱动切换、远端同步、团队共享账户、恢复包加密/密码保护、其它 IDE 账户管理、自动关闭用户 Cursor 做真实验收、发布或推送。

## How
- 复用现有 Manager、SQLite 白名单和 `clientApi` 边界；新增账户 store，并从 bridge 的 Cursor 进程 helper 抽取可注入的窄运行时适配，避免复制进程控制。
- 助手当前账户与 Cursor 客户端登录态分离；准备阶段零副作用，执行阶段用一次性 60 秒确认令牌和全局操作锁。
- 恢复包由后端直接写入用户选择的目标文件，不经 Wails 返回正文；它是含明文 token 的高风险文件，二次确认和受限权限不能替代用户妥善保管。
- 所有持久化使用同目录临时文件加 rename；真实状态库失败不静默重试，回滚失败与原错误同时上报。
- 旧登录方法名和返回合同保持不变一个发布周期，新 UI 使用会话式新方法；删除助手账户不改变独立的 Cursor 客户端登录态。

## Risk
- Blast radius: `cursoraccount` 授权、Cursor 状态库、进程重启、Wails bindings、首页账户 UI、i18n 和本地敏感文件。
- 凭据恢复包被复制或误传会导致账户接管；通过明确二次确认、后端直写、最小日志和可单独撤回导出入口降低暴露面，但首版不提供加密。
- 进程关闭或数据库写入中断可能破坏 Cursor 登录态；执行前备份 DB/WAL/SHM，逐键读回，失败反向恢复，恢复失败显式报告。
- 迁移或刷新竞态可能选择错误账户；完成式迁移保留 legacy 文件，刷新落盘前校验原账户 ID，旧接口保持兼容。
- Rollback plan: 按账户库、账户操作、切换事务、UI 四个主题逆序回退；保留 legacy 凭据和每次切换备份，可在 5 分钟内停用新 UI、恢复旧 current 和数据库文件。
